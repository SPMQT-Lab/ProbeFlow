# Architecture Refactor Baseline

This document records the behavioural safety net at the start of issue #52.
It does not certify scientific correctness. It identifies the existing tests
that refactors must preserve and records local environment limitations that
must not be mistaken for regressions.

## Starting point

- Branch: `task/52-initial-refactor`
- Architecture baseline commit: `e4c080f`
- Recorded: 16 August 2026
- Local interpreter: Python 3.12.3 on Windows
- Local key packages: NumPy 1.26.4, SciPy 1.15.3, Pillow 10.4.0,
  PySide6 6.6.3

The local Pillow and PySide6 versions are below the versions declared by the
project. CI on the supported dependency set remains authoritative.

## Initial local run

The unmodified baseline produced:

- Full `pytest -q`: Windows heap failure `0xc0000374` during Qt garbage
  collection in `_drain_qt_between_tests`, after the third test in
  `test_angle_update_and_dock_restore.py`.
- Backend run with Qt-owning modules excluded: 2,125 passed, 1 skipped, and 2
  environment-dependent failures.
- Failure 1: the installed Pillow 10.4.0 is below the required 12.2 minimum.
- Failure 2: Windows denied symlink creation in the resolved-path SXM safety
  test because Developer Mode or elevated symlink permission was unavailable.

These findings predate implementation changes. The Qt modules should be run in
smaller process groups on this workstation. CI and supported-version runs must
still pass before merge.

## Required checks

For every implementation pull request:

1. Run the tests directly related to the changed seam.
2. Run `pytest` on the complete supported environment.
3. Run GUI tests offscreen or in stable process groups where required.
4. Run `ruff check .`.
5. Run `git diff --check`.
6. Confirm that raw fixtures and source files remain unchanged.
